# 章节级写作模板

> 阶段二逐章写作时必须遵守的章节骨架。第 1 章为**强制框架**（用户/学校指定），其余章为默认骨架（可依学校模板调整）。以下用 XXX 指代课题对象（如系统管理对象：请假、报修、租赁……），写作时替换为实际对象名。

## 第 1 章　绪论（强制框架，标题与层级不得改动）

```
第1章　绪论
  1.1　研究背景
  1.2　国内外研究现状
    1.2.1　国外XXX平台发展现状
    1.2.2　国内XXX应用发展现状
  1.3　本文研究内容与技术路线
```

### 各小节写作要求

**1.1　研究背景**（约 2–3 段）
1. 对象价值：课题对象（XXX）在现实中的普遍性与重要性（为什么人们需要它）。
2. 问题引出：现状下 XXX 存在哪些具体问题（信息不实时 / 流程不透明 / 管理成本高 / 库存或资源不完整等，**从源码与真实材料归纳，不空喊**）。
3. 需求落点：为解决上述问题，本文设计并实现 XXX 系统是可行且有意义的（给出意义）。
4. 引文密集区，每条背景论断尽量带具名引用 [n]。

**1.2　国内外研究现状**（总起段 + 两个小节）
- 总起 1–2 句：说明从"国外平台 / 国内应用"两个维度综述，并说明综述目的（为本文方案提供依据）。
- **1.2.1　国外XXX平台发展现状**：
  - 写国外同业务/同模式的平台或业态（租用类、订阅类、共享类均可按实际），概括它们在系统设计上的共性做法（重视订单处理、信用审核、状态跟踪、风险控制等——按课题实际调整）。
  - 落到本文：哪些可借鉴、哪些因课题规模/场景不采纳（如"本文重点做 A/B/C，暂不涉及更复杂的 D"）。
- **1.2.2　国内XXX应用发展现状**：
  - 写国内同类系统/应用的现状与载体（移动应用、小程序、管理后台等按实际），概括已有系统的特点与**短板**（重展示轻流程、重后台轻前端、订单链路不完整等——从真实同类分析或文献归纳）。
  - 落到本文：针对短板，本文采用"载体 + 后台框架 + 后端框架"协同方式，做哪些功能、考虑哪些完整性与可行性。
- 两小节都须**主题式综述 + 给差距**，禁止只罗列文献不总结；禁止出现无主语的"有研究指出"（humanize A3，缺真实出处标【待作者补充】）。

**1.3　本文研究内容与技术路线**
- 研究内容一段：本文主要完成需求分析、系统设计、数据库设计、功能实现与测试验证；面向哪些角色分别提供什么。
- 技术路线一段：先……再……随后……最后……（需求→架构→库表→开发→测试的推进顺序，与后文各章呼应）。
- 可给一张技术路线/论文结构图（结构图须按第 7 节图规范走可编辑源）。

### 红线
- 第 1 章**标题层级严格等于上述 3 节 5 小节**，不得增删或改编号体系；若学校模板强制不同层级（如需要 1.2.3 国内……应用现状之不足），可在 1.2.2 内加 1.2.3 前先与用户确认。
- 国内外现状**必须**是"国外平台 / 国内应用"两个切面，不能写成"国外研究 / 国内研究"的论文罗列。
- 引文集中在第 1、2 章；第 1 章引用须能在参考文献中一一对应。

## 其余各章骨架（默认）

| 章 | 骨架 |
|---|---|
| 第2章　相关技术介绍 | 2.1 载体技术（小程序/前端框架）· 2.2 后台前端框架 · 2.3 后端框架 · 2.4 持久层 · 2.5 数据库 · 2.6 鉴权/上传/其他 · 2.7 扩展技术（AI 等）——每节：是什么→为何选→本项目如何用 |
| 第3章　系统需求分析 | 3.1 总体需求（3.1.1 角色分析 · 3.1.2 功能需求 · 3.1.3 非功能需求）· 3.2 可行性（技术/经济/操作）· 用例图 |
| 第4章　系统设计 | 4.1 设计流程（4.1.1 总体流程 · 4.1.2 关键业务时序）· 4.2 总体结构（架构图/功能结构图）· 4.3 数据库设计（概念→逻辑→物理 + 表） |
| 第5章　系统实现 | 5.1 用户端功能实现（逐模块）· 5.2 管理端功能实现（逐模块）· 关键流程 + 真实运行截图 |
| 第6章　系统测试 | 6.1 目的 · 6.2 方法与环境 · 6.3 内容（按端/流程/权限/扩展分小节）· 6.4 结论 |
| 结　　论 / 参考文献 / 致　　谢 / 附　　录 | 结论(完成工作+局限+展望)；参考文献(与正文 [n] 闭合)；致谢得体；附录有实际内容(空则删) |

> 章内小节数按证据与篇幅可增可减，但**编号体系、标题样式、图表编号规则**（见 01-writing-standards §3/§6）不变。
