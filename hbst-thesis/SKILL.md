# 河北科技师范学院本科毕业论文写作（hbst-thesis）

把一套真实源码变成一篇**可直接提交**的本科毕业论文。适用于河北科技师范学院（含采用同类"封面-声明-摘要-目录-六章正文-参考文献-致谢-附录"结构的本科院校）。**学校模板/导师要求永远优先于本技能内的一切默认值**；本技能在用户未给模板时内置了从该校真实论文逆向出的格式基线。

## 使用流程（三个阶段，顺序不可颠倒）

```
阶段一  通读源码，建立证据
阶段二  按写作规范逐章成文 + 图表 + 降AIGC优化（写作与优化交替进行，非两遍孤立的通读）
阶段三  生产 docx + 提交前检查
```

> 关键纪律：**证据先行、写作在后、优化随章**。禁止拿到源码直接开写自由散文；禁止全文写完后再统一"去AI味"（那会制造风格断层，见降AIGC规范 C1/X5）。

## 阶段一：通读源码，建立证据

目标产出：一份 `paper-context/` 工作区（仅内部使用，**禁止把其中的"证据/待补/根据源码"等措辞写进论文正文**，见 references/04-thesis-voice.md）。

1. 索要材料（按优先级，缺哪个就明说缺哪个，不硬写）：
   1. 学校 Word 模板 `.docx`（给了则先做**模板逆向**，见步骤 2）
   2. 项目源码/仓库路径（必需）
   3. 数据库证据：`*.sql`、实体类、ORM Model、迁移文件、表结构导出、`application*.yml` 中可推断的库表线索
   4. 接口证据：Controller/路由/Service
   5. 截图、运行日志、测试报告/用例
   6. 参考文献要求/已有文献清单
   7. 已有的论文草稿（若有）
2. 若给了学校模板 `.docx`：按 [references/03-template-reverse.md](references/03-template-reverse.md) 逆向出**模板画像**（分节/字体字号/页边距/标题样式/图题注表题注样式/三线表规格/页码规则/参考格式），存入 `paper-context/template-profile.yaml`。本技能内置的默认基线就是河北科技师范学院画像，见同文件。
3. 源码证据提取：用 [scripts/evidence_scan.py](scripts/evidence_scan.py)（若运行环境允许）扫描源码目录，或手动按证据类别梳理，产出并核对：
   - 技术栈（语言/框架/数据库/中间件/第三方服务，含版本线索）
   - 功能模块清单（前端页面/端、后端模块）
   - 角色与权限模型（登录、token、角色区分、越权控制）
   - 核心业务流程（须能画出流程图：下单/支付/状态机/审批等）
   - 数据库表与字段（尽量到字段级：表名/字段/类型/注释/枚举值/索引/关联）
   - API 清单（路径/方法/用途/入参出参要点/统一前缀）
   - 测试材料（用例/日志/报告/断言）
   - 截图登记（哪些界面有真图，哪些缺失）
4. 建立 **图表登记** `paper-context/figure-registry.yaml`：规划第 3–6 章所有图与表的编号、题注文字、证据来源、状态（`ready` / `needs_user_screenshot` / `pending_evidence`）。规划数量参考：正常系统类论文第 3–6 章应 ≥8 图；第 4 章数据库 ≥ 每表一张三线表 + 总E-R + 核心实体单实体E-R。规划不足 8 图须说明理由。
5. 把关键事实填进 `paper-context/spec.yaml`（题目、角色、功能、技术栈、流程、表、接口、测试、缺证清单），作为阶段二逐章写作的"唯一事实源"。
6. **证据缺口清单**：凡源码/材料无法支撑的内容（无截图的界面、无日志的测试结论、无文献来源的引文、无数据库证据的表），一律登记为缺口并【待用户补充】，禁止编造（见红线）。

**红线（全程有效，违反即停）**：
- 禁止编造：功能、接口、数据库字段、测试结果、截图、实验数据、参考文献（含 DOI/卷期页码）、学校规定。
- 证据缺失时输出"缺什么"，不假装有。
- 数据库证据缺失时：若项目有真实结构化产物（YAML/JSON/JSONL/Markdown 登记表/日志），可改建"数据对象模型"并**在正文明确说明它不是物理业务数据库**；两者都没有则在第 4 章列出证据缺口，不跳过也不编造。
- 截图与测试结果同理：拿不到真图就登记 `needs_user_screenshot`，拿不到测试日志就只写测试计划/用例与缺口，**不做假图假结果**。

## 阶段二：写作与降AIGC优化

### 2.1 写作规范（强制基线）

先读 [references/01-writing-standards.md](references/01-writing-standards.md)（该校通用写作规范全文，从真实论文逆向+泛化）。**其内容一点都不能丢**：它定义了封面/声明/摘要/目录/正文/参考文献/致谢/附录的写法、六章骨架、图表规范、语言红线、Word/PDF 提交前双检查清单。每章动笔前先读对应章节的规范条款。

章节骨架默认（学校模板/导师要求可改）：

| 章 | 标题 | 必含 |
|---|---|---|
| 1 | 绪论 | 背景、国内外现状（主题式综述并给差距）、研究内容与技术路线。引用集中区 |
| 2 | 相关技术介绍 | 每技术：是什么→为何选→本项目如何用。引用集中区。只用项目真用的技术 |
| 3 | 系统需求分析 | 总体需求、角色与用例（配用例图）、功能需求、非功能需求、可行性 |
| 4 | 系统设计 | 设计流程（配流程图）、总体结构（架构图/功能结构图）、数据库设计（总E-R+单实体E-R+字段三线表） |
| 5 | 系统实现 | 按模块：实现说明+关键流程+真实界面截图（图注在下）。禁止放测试内容 |
| 6 | 系统测试 | 测试目的/方法、测试环境表（版本必须填全）、用例表、结果；缺独立结论章时章末补完成工作/不足/展望 |
| 结/致谢/附录 | 结　论 / 致　谢 / 附　录 | 结论概括+局限+展望；致谢得体；附录有实际内容（空附录=删掉） |

写作语言规范（与降AIGC共用，避免写完再返工）：
- 见 [references/04-thesis-voice.md](references/04-thesis-voice.md)：正文用"本文设计并实现了/本系统采用/该模块主要完成/测试结果表明"，**禁止**"根据源码/从代码证据看/待补/占位/当前材料"等过程措辞、本地路径、源码文件名（`init.sql`/`pom.xml`）进入正文。
- 术语唯一、中英对照、无口语广告腔、无重复字句、标点全角统一（完整规则在 writing-standards §8 与 humanize §4）。

**章节框架（强制）**：见 [references/06-chapter-templates.md](references/06-chapter-templates.md)。第 1 章标题与层级**严格按"1.1 研究背景 / 1.2 国内外研究现状（1.2.1 国外XXX平台发展现状 / 1.2.2 国内XXX应用发展现状）/ 1.3 本文研究内容与技术路线"**，不得增删层级；其余章按默认骨架。

### 2.2 图表生产规则

- 图题注在图**下**、表题注在表**上**，居中；编号按章：`图X.Y`/`表X.Y`；每图表先有正文引导句再出现。
- 表格一律**三线表**（顶线/栏目线/底线，无竖线无内部横线）；跨页表：表头行重复 + 行不跨页断行 + 续页标注"续表 X.Y"。docx 层的落法见 [references/05-docx-production.md](references/05-docx-production.md)。
- **结构图规范（强制）**：见 [references/07-diagram-standards.md](references/07-diagram-standards.md)。除"系统运行截图"外的一切图（用例图/流程图/时序图/架构图/模块结构图/E-R 图/技术路线图）**必须出自可编辑矢量源（`.vsdx` 或 `.drawio`）**，docx 内嵌其高清导出图，可编辑源随论文留档并在 `figure-registry.yaml` 登记。**禁止用 matplotlib/绘图脚本直出的位图 PNG 当作结构图交付**（会被要求提供 Visio 原图）。生成工具：优先本机 Visio COM；无 Visio 时用 [scripts/gen_diagram.py](scripts/gen_diagram.py) 生成 `.drawio` 可编辑源，再由 draw.io 导出 PNG（插图）与 `.vsdx`（留档/交审）。
- 截图：真图、清晰、无测试脏数据、无占位文字、宽高不过大撑页（显示宽约 10–15cm）。

### 2.3 降AIGC优化（随章或成文后整体执行）

先读 [references/02-humanize-standards.md](references/02-humanize-standards.md)（降AIGC规范全文，**内容零丢失**），并**必须**遵守：
- 开头先做**场景决策**（§0）：若用户场景**明令禁止** AI 参与（闭卷/禁AI课程）→ 明确告知本规范不适用、不执行；若"允许但需披露"→ 执行并在交付时提醒披露义务（§7 模板）。学校毕业论文默认按"允许 AI 辅助但需披露"档执行，交付时附披露提醒。
- 按 A（语义层：A1 脱稿重写/A2 段结构手术/A3 具名引用/A4 真实锚点）> B（句层）> C（文档层）执行；**高危段（引言/综述/讨论/结语）必须 A1 脱稿重写**，禁止只做同义词/标点级修补（X1/X4）。
- 忠于原文事实与数据；缺真实素材标【待作者补充】；**禁止为降 AI 率虚构数据/文献/经历**（X8，性质是学术不端）。
- 执行"有限变异"：先定全文基础嗓音，再围绕它波动（B3 边界、C1 嗓音一致），**禁止只改疑似标红段**（X5 会风格断层）；全文整体处理。
- 完成 A/B/C 处理后，跑第 5 节自检 S1–S12（模板链/空壳句头/超长句/节奏/真实锚点/具名引用/句式有界/结构非闭环/无断层/忠实性/披露/免责），交付时附 JSON 自检摘要。
- 处理顺序纪律：**先降 AIGC 痕迹、后跑查重**（改写可能抬查重率）；复测留 ≥2–5 点裕量；不针对单一检测器过拟合（C6）。
- 禁止"保证通过/100% 人类"表述；说明检测是概率性、版本相关的。

### 2.4 写作过程中维护

- 每写完一章更新 `figure-registry.yaml` 状态与 `spec.yaml` 缺证清单。
- 图表编号、正文引用编号一致性随写随查。

## 阶段三：docx 生产 + 提交前检查

### 3.1 生成 .docx

优先用 `python scripts/build_docx.py 论文稿.md --out 论文.docx` 一键生成（格式约定见脚本头注释：front matter 填封面字段、`# 目　　录` 下放 `<!--TOC-->`、markdown 表格即三线表、`![图X.Y　题注](路径)` 图注在图下）。脚本已按模板画像实现 6 分节、封面、声明页、罗马/阿拉伯页码域、正文页眉、TOC 域、三线表。**生成后必须在 Word/WPS 中全选按 F9 更新域**（目录与页码显示正确），再导出 PDF 做版面核对。

不用脚本、直接以 docx 技能/工具排版时，也必须满足 [references/05-docx-production.md](references/05-docx-production.md) 的全部落法：

- 分节与页码：封面节/声明节无页码；中文摘要起罗马 i；目录罗马续；正文起阿拉伯 1；参考文献/致谢/附录阿拉伯续。声明与授权书**各占一页**。
- 标题全部使用 Word 内置标题 1/2/3 样式；目录用自动目录域（`TOC \o "1-3"`）。
- 页脚页码为 PAGE 域（fldChar 必须用 `w:fldCharType`）；页眉"河北科技师范学院学士学位论文"（正文节起）。
- 表格三线表 + 跨页续表表头重复；图题注在图下、表题注在表上。
- 正文章节末尾的图/表不要"孤行/分离"：图与其引导句尽量同页，必要时人工分页调整。

### 3.2 提交前检查（可执行闸门）

产出后按顺序跑三道检查，任一不过就修复并重跑，不得声称"完成"：

1. **内容/证据闸门**：脚本 [scripts/check_text_quality.py](scripts/check_text_quality.py)（或人工等价核对）：
   - 章节完整、无手打目录冒充域、无"待补/初稿/TBD/后续补充"等未完成措辞进入正文（除确需用户补充处单列清单）
   - 图/表编号连续、题注在正确侧、正文引用与题注一一对应
   - 引用 `[n]` 与参考文献列表闭合（正文引用都有条目、无重复编号）
   - 正文无 AI 工作流语言/过程措辞/本地路径/源码文件名
   - 中文字数达标（正常本科系统类论文正文 ≥ 约 1 万字，学校另有要求从其要求）
2. **降AIGC自检**：跑 humanize §5 的 S1–S12 清单并输出 JSON。
3. **docx/PDF 版面闸门**：将 `.docx` 导出 PDF（Word/WPS/自动化均可），逐项核对 writing-standards §10 清单：目录页码与实际一致（抽查 ≥3 处）、封面无页码/正文阿拉伯、无异常空白页、无孤行、无图注分离、无大图撑页留白、跨页表表头重复、无乱码方框、截图清晰未变形。
   - 能跑则用 [scripts/check_docx_structure.py](scripts/check_docx_structure.py) 对 `.docx` 做结构级抽查（分节/标题样式/域/三线表边框/续表表头）；跑不了就按 §10 人工清单核对并说明。

### 3.3 交付报告（必附）

完成时输出：
1. 生成了什么（文件路径、章节、图表数）
2. 三道闸门的检查结果与证据（exit code / 清单勾选）
3. 仍需人工确认项：缺证清单、待补截图、参考文献待用户核对项
4. 披露提醒：若场景要求披露 AI 辅助，给出 humanize §7 模板
5. 免责：不构成任何检测通过保证

## 环境与脚本说明

- 纯 Python 脚本依赖 `python-docx`（`pip install python-docx`）；其余检查尽量用标准库。脚本以"证据辅助/闸门检查"为定位，不是写作本身。
- 若运行环境有可用的 docx/Office 技能或工具，可借其完成 3.1/3.2 的排版与渲染，但**规范内容一律以本技能 references/ 下的两份规范为准，不得缩减**。
- 无法运行脚本时，按各 references 内嵌的人工检查清单执行，并在交付报告中注明"脚本未运行，检查为人工执行"。

## 红线速记

1. 学校/导师规则 > 本技能默认值。
2. 不编造任何证据（功能/字段/接口/测试/截图/文献/数据/学校规定）；缺失就列缺口。
3. 第 5 章不放测试内容、第 6 章不放功能截图、无独立结论章要求则不设第 7 章。
4. 正文禁止过程措辞与证据语言（voice 规则）。
5. 降 AIGC 不虚构、不隐瞒、不保证过检、不针对单检测器过拟合。
6. `.docx` 变更后必须重跑闸门；闸门不过不得声称完成。
